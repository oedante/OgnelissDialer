# Выгрузки российской системы и плана нумерации

Сюда кладутся файлы Россвязи: `ABC-3xx.csv`, `ABC-4xx.csv`, `ABC-8xx.csv`,
`DEF-9xx.csv` (разделитель `;`, кодировка UTF-8 с BOM).

Сами выгрузки в репозиторий не кладём: вместе они весят около 60 МБ,
а нужны только при пересборке. В приложение попадает результат —
`app/src/main/assets/numbering_plan.bin`, около 4 МБ.

## Как обновить

1. Скачать свежие выгрузки с сайта Россвязи и положить их в эту папку.
2. `python3 scripts/build_numbering.py`
3. Проверить, что размер `numbering_plan.bin` изменился незначительно:
   резкое падение означает, что часть файлов не прочиталась.
4. Закоммитить только `numbering_plan.bin`.

Формат готового файла описан в шапке `scripts/build_numbering.py`.


## Почему не carrier из libphonenumber

Вопрос возникает сам собой: у libphonenumber есть определитель оператора
по номеру — зачем держать свой файл на четыре мегабайта?

Сверка с их данными (`resources/carrier/ru/7.txt`), сентябрь 2026:

| | Реестр Россвязи | carrier libphonenumber |
|---|---|---|
| Диапазонов/префиксов по России | 419 551 | 988 |
| Кодов DEF представлено | все | 41 |
| Коды 910, 916, 918 | есть | **нет вовсе** |
| Код 967 | разбит по операторам | один префикс «Билайн» |
| Городские номера | есть | нет |
| Линии 8-800 | есть | нет |
| Регион | есть | **не даёт вообще** |

Коды 910, 916 и 918 — это МТС, Мегафон и Билайн в Москве и на юге,
десятки миллионов номеров. Отдать 967 целиком одному оператору — ровно
то угадывание по коду, от которого мы ушли, заведя реестр.

Поэтому carrier подключён как **запасной источник для других стран**,
а по России работает реестр. Разбор — в `NumberInfoRepository`,
рядом с `carrierMapper`.
