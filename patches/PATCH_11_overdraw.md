# Наложение слоёв: разбор по скриншотам

Замер сделан, и он подтвердил догадку с запасом. Дальше можно не гадать.

## Что показывают цвета

| Цвет | Слоёв | Где на ваших скриншотах |
|---|---|---|
| Без цвета | 0 | — |
| Синий | 1 | Фон под списком |
| Зелёный | 2 | Область клавиатуры |
| **Розовый** | **3** | **Все карточки журнала, все клавиши** |
| **Тёмно-красный** | **4+** | **Кнопки SIM 1 / SIM 2, кнопка клавиатуры** |

Норма для списка — синий и зелёный. Розовый допустим точечно.
Тёмно-красный не допустим нигде: каждый пиксель там закрашивается
четыре раза и более.

**Список во весь экран розовый — это и есть причина рывков при
прокрутке.** Видеоядро успевает, но с трудом, и на быстрой прокрутке
кадры начинают выпадать.

## Причина 1: тема окна светлая, а рисуем поверх

### Файл: `app/src/main/res/values/themes.xml`

```xml
    <style name="Theme.OgnelissDialer" parent="android:Theme.Material.Light.NoActionBar" />
```

Система заливает окно белым фоном темы **до** того, как Compose
нарисует свой. Это первый лишний слой **на всём экране разом** —
он и даёт синий фон вместо бесцветного.

**Заменить на:**

```xml
<resources>
    <!--
      ФОН ОКНА НЕ ЗАЛИВАЕТСЯ.

      Система рисует windowBackground до того, как Compose нарисует
      свой фон. Получается два слоя на всей площади экрана: сначала
      белый от темы, поверх — наш.

      На отладке наложения это видно как синий фон вместо бесцветного,
      и этот слой добавляется ко ВСЕМУ, что нарисовано выше.

      Прозрачный фон окна убирает его целиком. Compose рисует
      непрозрачный фон сам, так что просвечивать нечему.
    -->
    <style name="Theme.OgnelissDialer" parent="android:Theme.Material.Light.NoActionBar">
        <item name="android:windowBackground">@null</item>
        <item name="android:windowDisablePreview">false</item>
    </style>

    <style name="Theme.OgnelissDialer.InCall" parent="Theme.OgnelissDialer" />
</resources>
```

⚠️ Если после этого при запуске мелькает чёрный кадр — вернуть
`@null` обратно и вместо него поставить цвет, совпадающий с фоном
темы приложения. Тогда слой останется, но хотя бы не будет
белой вспышки на тёмной теме.

## Причина 2: карточка журнала рисует фон трижды

Розовый на всех карточках складывается из:

1. фон окна (см. причину 1);
2. `Card` со своим `containerColor`;
3. `SwipeRevealRow` — фон панели действий под строкой;
4. внутренний `Row` (после правки 10 — фон отметки выбора).

### Файл: `ui/components/CallLogCard.kt`

**Оставить ровно один фон** — на содержимом строки, потому что именно
оно знает про отметку выбора:

```kotlin
    /*
     * ОДИН СЛОЙ ФОНА НА КАРТОЧКУ.
     *
     * Card отвечает только за форму и отступы. Цвет задаёт содержимое:
     * оно знает про режим выбора, а Card — нет, и раньше они красили
     * одну и ту же площадь по очереди.
     */
    Card(
        colors = CardDefaults.cardColors(containerColor = Color.Transparent),
        elevation = CardDefaults.cardElevation(defaultElevation = 0.dp),
        shape = MaterialTheme.shapes.medium,
        modifier = Modifier
            .fillMaxWidth()
            .padding(horizontal = 12.dp, vertical = 3.dp)
            .semantics(mergeDescendants = true) {
                contentDescription = row.accessibilityLabel
            }
    ) {
```

### Файл: `ui/components/swipe/SwipeRevealRow.kt`

Фон панели рисовать **только когда строка сдвинута**:

```kotlin
        /*
         * Фон панели появляется только при сдвиге.
         *
         * Раньше он рисовался всегда, включая закрытое состояние —
         * то есть закрашивал площадь под каждой строкой списка,
         * которую тут же перекрывало содержимое. Слой на весь экран
         * ради того, что не видно.
         */
        if (offset != 0f) {
            // ... существующая отрисовка панели и подсказки
        }
```

## Причина 3: клавиши и кнопки SIM

Тёмно-красный на кнопках SIM — четыре слоя и больше:

1. фон окна
2. `Surface` нижней панели (`surfaceContainer`)
3. `Button` со своим фоном
4. иконка с фоном + рябь нажатия

### Файл: `ui/components/BottomControlPanel.kt`

Панель уже непрозрачна, поэтому фон окна под ней рисовать незачем.
Но убрать его выборочно нельзя — значит, экономим на другом.

**Клавиши: убрать `Surface`, рисовать фон напрямую.**

### Файл: `ui/components/Dialpad.kt`

**Найти:**

```kotlin
                    Surface(
                        shape = OgnelissShapeTokens.dialKey,
                        color = MaterialTheme.colorScheme.surfaceContainerHighest,
                        modifier = Modifier
```

**Заменить на:**

```kotlin
                    /*
                     * Фон клавиши рисуется напрямую, без Surface.
                     *
                     * Surface помимо фона создаёт слой для тени и ряби,
                     * даже когда тень нулевая. Для двенадцати клавиш,
                     * лежащих на непрозрачной панели, это двенадцать
                     * лишних слоёв на каждом кадре.
                     *
                     * Modifier.background рисует ровно один прямоугольник
                     * со скруглением — ничего больше здесь и не нужно.
                     */
                    Box(
                        modifier = Modifier
                            .weight(1f)
                            .padding(3.dp)
                            .heightIn(min = Dimens.MIN_TOUCH_TARGET)
                            .height(appearance.dialKeyHeight)
                            .clip(OgnelissShapeTokens.dialKey)
                            .background(MaterialTheme.colorScheme.surfaceContainerHighest)
```

Порядок важен: `clip` перед `background`, иначе фон нарисуется
прямоугольником и скругление будет закрашено.

Импорты:

```kotlin
import androidx.compose.foundation.background
import androidx.compose.ui.draw.clip
```

### Кнопки SIM

### Файл: `ui/components/CallButtons.kt`

Кнопка вызова — главный элемент, ей тень нужна. Но иконка внутри
рисует свой фон:

**Найти** отрисовку иконки и убедиться, что у неё нет `Surface`
или `background`. Если есть — убрать: цвет иконки задаётся `tint`,
отдельный фон ей не нужен.

---

## Чего делать НЕ нужно

**Не убирайте фон у нижней панели.** Она непрозрачна намеренно:
список уходит под неё, и без фона он просвечивал бы сквозь клавиши.
Два слоя там — правильная цена.

**Не убирайте скругления ради слоёв.** Разница в производительности
незаметна, а форма несёт смысл.

## Как проверить результат

Тот же режим отладки наложения. Цель:

| Область | Было | Цель |
|---|---|---|
| Фон списка | Синий (1) | Без цвета (0) |
| Карточки | Розовый (3) | Синий или зелёный (1–2) |
| Клавиатура | Зелёный (2) | Зелёный (2) |
| Клавиши | Розовый (3) | Зелёный (2) |
| Кнопки SIM | Тёмно-красный (4+) | Розовый (3) |

Розовый на кнопках SIM останется и это нормально: панель, кнопка
и её содержимое — три осмысленных слоя.

После правок замерить кадры:

```
adb shell dumpsys gfxinfo com.ogneliss.dialer reset
# прокрутить журнал 5 секунд
adb shell dumpsys gfxinfo com.ogneliss.dialer | grep -A 3 "Janky frames"
```

Если доля janky упала, но не до нуля — оставшееся ищите в перерисовках
(синие столбики в профилировщике), это уже другая болезнь
и лечится правкой 05.
