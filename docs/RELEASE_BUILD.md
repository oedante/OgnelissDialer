# Как собрать релизную версию

## Коротко

```bash
./gradlew assembleRelease
```

APK окажется в `app/build/outputs/apk/release/`.

Без файла с ключом сборка подпишется отладочным — на телефон
установится, в Google Play не примут. Для магазина нужен свой ключ,
см. ниже.

---

## Зачем собирать release, а не debug

Debug медленнее **в два-пять раз**, и оценивать по нему скорость
бессмысленно. Причины:

- компилятор Compose оставляет проверки и трассировку — в release
  они вырезаются;
- не работает R8: код не инлайнится, вызовы не оптимизируются;
- нет предкомпиляции: методы интерпретируются, пока ART не решит
  их скомпилировать;
- включён `StrictMode`, проверяющий каждое обращение к диску.

**Сначала соберите release и оцените скорость там.** Возможно,
дальнейшая оптимизация не понадобится вовсе.

---

## Свой ключ подписи

Нужен только для Google Play. Для проверки на своём телефоне
пропустите этот раздел.

### 1. Создать хранилище

```bash
keytool -genkey -v -keystore ogneliss-release.jks \
  -keyalg RSA -keysize 2048 -validity 10000 -alias ogneliss
```

Спросит пароль и данные владельца. **Пароль запишите отдельно:**
восстановить его нельзя, а без него нельзя выпустить обновление —
Google Play не примет APK, подписанный другим ключом.

Файл `.jks` храните вне репозитория и сделайте резервную копию.

### 2. Указать путь к ключу

Создайте `keystore.properties` в корне проекта (рядом с `settings.gradle.kts`):

```properties
storeFile=D:/keys/ogneliss-release.jks
storePassword=ваш_пароль
keyAlias=ogneliss
keyPassword=ваш_пароль
```

Файл уже в `.gitignore` — в репозиторий не попадёт.

### 3. Собрать

```bash
./gradlew assembleRelease
```

---

## Для публикации нужен не APK, а AAB

Google Play принимает App Bundle: он позволяет доставлять устройству
только нужную часть ресурсов.

```bash
./gradlew bundleRelease
```

Результат: `app/build/outputs/bundle/release/app-release.aab`

С 1.8.2 `bundleRelease` без `keystore.properties` не собирается: бандл
с отладочной подписью Play всё равно не примет.

---

## Выпуск APK на GitHub (1.8.2; с 1.9.0 — и кнопкой на сайте)

Бандлы для Google Play собираются у себя. Для тех, кто ставит не из Play
(нет Play на телефоне, Huawei без сервисов Google и т. п.), APK
выкладывается в Releases репозитория: `.github/workflows/release.yml`
собирает его по метке версии.

### Ключ — отдельный, не ключ загрузки Play

Приложения из Google Play подписывает своим ключом Google: бандлы
публикуются только с подписью приложений в Google Play. Поэтому APK
с GitHub поверх версии из Play не встанет, каким бы ключом его
ни подписать. Ключ загрузки в GitHub класть незачем — для выпусков
на GitHub заводится свой.

Создать один раз (keytool есть в Android Studio):

```powershell
& "C:\Program Files\Android\Android Studio\jbr\bin\keytool.exe" -genkeypair -v `
  -keystore D:\keys\ogneliss-github.jks -alias ogneliss-github `
  -keyalg RSA -keysize 4096 -validity 10000
```

⚠️ Сохраните файл и пароли так же бережно, как ключ загрузки: с потерей
ключа выпуски с GitHub больше не встанут поверх уже установленных — людям
придётся удалять приложение и ставить заново.

### 1. Ключ — в текст

```powershell
[Convert]::ToBase64String([IO.File]::ReadAllBytes("D:\keys\ogneliss-github.jks")) | Set-Clipboard
```

### 2. Секреты и переменная

github.com/oedante/OgnelissDialer → Settings → Secrets and variables →
Actions.

На вкладке **Secrets** — «New repository secret», четыре:

| Имя | Значение |
|---|---|
| `APK_KEYSTORE_BASE64` | вставить из буфера (шаг 1) |
| `APK_KEYSTORE_PASSWORD` | пароль хранилища |
| `APK_KEY_ALIAS` | `ogneliss-github` |
| `APK_KEY_PASSWORD` | пароль ключа |

После этого скопируйте любой другой текст — ключ не должен остаться
в буфере обмена.

На вкладке **Variables** — «New repository variable» `APK_CERT_SHA256`:
отпечаток SHA-256 сертификата (keytool -list -v -keystore
D:\keys\ogneliss-github.jks — строка «SHA256:»; у ключа, которым собран
v1.8.2, — `D4:D3:09:89:85:28:AF:C3:64:B7:7E:F1:5E:FD:12:80:D6:26:F4:B3:51:43:6A:34:B6:D0:6C:D6:AB:3D:E5:8B`). Не обязательно,
но с ним сборка остановится, если ключ в секретах по ошибке заменят
другим: APK с другим ключом поверх установленного не встанет.

### 3. Выпуск

Версия в `app/build.gradle.kts` уже поднята и закоммичена. Дальше —
любой из двух путей (с 04.11 оба рабочие):

```powershell
git tag v2.5.0
git push origin v2.5.0
```

или на сайте: Releases → «Draft a new release» → «Choose a tag» →
`v2.5.0` → «Create new tag on publish», ветка master → «Publish
release». Заголовок и текст можно не заполнять: сборка заменит их.

Минут через 10–15 в выпуске появятся `OgnelissDialer-2.5.0.apk`,
контрольная сумма `.sha256` и описание — «Что нового» на русском
и английском из `store/whats_new_2.5.0.txt`, как поставить, отпечаток
подписи. Метка должна совпадать с versionName (`v2.5.0` ↔ `2.5.0`),
иначе сборка остановится.

До 04.11 работал только первый путь: выпуск, созданный на сайте
(так был создан v1.8.2), ронял сборку на последнем шаге — «a release
with the same tag name already exists». Теперь сборка прикладывает APK
к уже созданному выпуску (`docs/BUILD_TROUBLESHOOTING.md`).

**Пробная сборка без выпуска:** Actions → «Выпуск APK на GitHub» →
Run workflow — APK и описание будут артефактом запуска (7 дней).

### Что проверяет сборка

- секреты на месте — иначе ошибка с названием недостающего;
- метка совпадает с версией в коде;
- APK подписан не отладочным ключом, а если задан `APK_CERT_SHA256` —
  тем же, что прошлые выпуски;
- в выпускной сборке нет разрешения INTERNET.

### Безопасность

Секреты GitHub зашифрованы и в журнале сборки заменяются звёздочками.
Метку и ручной запуск может только владелец репозитория; запросы
на слияние этот workflow не запускают, копиям репозитория GitHub
секреты не отдаёт. Ключ лежит только во временной папке машины GitHub
и удаляется в конце запуска. Ключ загрузки Google Play на GitHub
не попадает вовсе.

## Baseline Profile — до сборки

Даёт **20–30 % к скорости холодного старта и первой прокрутки**.
Требует подключённого устройства:

```bash
./gradlew :app:generateBaselineProfile
```

Команда прогонит сценарии на телефоне и запишет правила
в `app/src/main/baseline-prof.txt`.

**Полученный файл закоммитьте** — он часть исходников. Сейчас там
только комментарии, то есть механизм не работает вовсе.

## Что проверить после установки release

Две вещи ловят ошибки, которых нет в debug:

| Проверка | Что означает провал |
|---|---|
| **Настройки не сбросились** | Обфускация задела имена enum — проверьте правило `valueOf` в `proguard-rules.pro` |
| **Входящие вызовы принимаются** | R8 вырезал сервисы телефонии — проверьте `-keep class com.ogneliss.dialer.call` |

Плюс общее: открытие, прокрутка журнала, поиск — плавность должна
заметно отличаться от debug.

## Полезное

**Установить поверх debug-версии.** Они сосуществуют: у отладочной
суффикс `.debug` в имени пакета, и в списке приложений она называется
«Ogneliss (debug)».

```bash
adb install -r app/build/outputs/apk/release/app-release.apk
```

**Посмотреть, что попало в сборку:**

```bash
./gradlew assembleRelease --scan
```

**Отчёт о стабильности Compose** — какие классы компилятор считает
нестабильными:

```bash
./gradlew assembleRelease "-Pcompose.metrics=true"
```

Результат в `app/build/compose_metrics/`.
