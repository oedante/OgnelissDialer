# Сборка Ogneliss Dialer в Android Studio

Инструкция для сборки и запуска на собственном устройстве.
Проверялась на Windows; на macOS и Linux отличаются только пути
и вместо `gradlew.bat` используется `./gradlew`.

---

## 1. Что понадобится

| Компонент | Требование | Где взять |
|---|---|---|
| Android Studio | Ladybug (2024.2) или новее | developer.android.com/studio |
| JDK | **17** | Идёт в комплекте со Studio |
| Android SDK | Platform 35 и выше | SDK Manager внутри Studio |
| Build Tools | Соответствующие compileSdk | SDK Manager |
| Устройство | Android 8.0 (API 26) и выше, **с SIM-картой** | — |

### Почему нужно реальное устройство

Эмулятор для этого проекта почти бесполезен:

- в нём **нет входящих вызовов** — половину функций проверить нельзя;
- нет SIM-карт, значит не проверить выбор карты и бейджи;
- нет датчика приближения — не проверить, гаснет ли экран у уха;
- телефония работает частично, и приложение может не получить роль
  диалера по умолчанию.

Собрать и запустить на эмуляторе можно, но выводы о работоспособности
делать по нему нельзя.

## 2. Открытие проекта

1. **File → Open**, выбрать корневую папку проекта
   (ту, где лежит `settings.gradle.kts`).
   Не подпапку `app` — иначе Studio откроет её как отдельный проект.

2. Дождаться первого Gradle Sync. Он пойдёт в интернет за зависимостями,
   первый раз это несколько минут.

3. Проверить JDK: **File → Settings → Build, Execution, Deployment →
   Build Tools → Gradle → Gradle JDK** должен быть **17**.
   Версия 21 или 11 даст ошибки компиляции Kotlin.

### Если Gradle wrapper отсутствует

В архиве нет папки `gradle/wrapper` — она генерируется. Studio обычно
предлагает создать её сама. Если нет, выполнить в корне проекта:

```
gradle wrapper --gradle-version 8.9
```

Либо создать `gradle/wrapper/gradle-wrapper.properties` вручную:

```properties
distributionBase=GRADLE_USER_HOME
distributionPath=wrapper/dists
distributionUrl=https\://services.gradle.org/distributions/gradle-8.9-bin.zip
zipStoreBase=GRADLE_USER_HOME
zipStorePath=wrapper/dists
```

### local.properties

Создаётся автоматически при первом открытии. Если его нет, создать
в корне проекта:

```properties
sdk.dir=C\:\\Users\\ИМЯ\\AppData\\Local\\Android\\Sdk
```

Файл в репозиторий не попадает: путь к SDK у каждого свой.

## 3. Согласование версий — самое важное

Три компонента обязаны быть совместимы: **AGP, Kotlin и KSP**.
Это причина большинства ошибок сборки.

Открыть `gradle/libs.versions.toml` и проверить блок `[versions]`:

```toml
agp = "8.7.3"
kotlin = "2.1.0"
ksp = "2.1.0-1.0.29"     # ← первая часть ОБЯЗАНА совпадать с kotlin
```

**Правило KSP.** Версия состоит из двух частей: `<версия Kotlin>-<версия KSP>`.
Если обновляете Kotlin — обязательно обновите и KSP. Симптом
несовпадения в логе:

```
ksp-2.2.10-2.0.2 is too old for kotlin-2.4.10
```

Актуальную пару смотреть на https://github.com/google/ksp/releases

**Про Hilt.** Он тоже привязан к версии Kotlin. Если после обновления
Kotlin появляются ошибки генерации, проверить совместимость на
https://github.com/google/dagger/releases

Совет: если проект не собирается сразу после скачивания — **не обновляйте
версии**. Соберите на тех, что указаны, убедитесь, что работает,
и только потом обновляйтесь по одной.

## 4. Первая сборка

### Быстрая проверка до сборки

Экономит минуты: ловит ошибки, которые иначе всплывут только
при компиляции.

```
python3 scripts/prebuild_check.py
python3 scripts/audit.py
```

Нужен Python 3. Если его нет, шаг можно пропустить.

### Сборка

В Studio: **Build → Make Project** (Ctrl+F9).

Или из терминала в корне проекта:

```
gradlew.bat assembleDebug
```

Готовый APK окажется в `app/build/outputs/apk/debug/`.

### Если мешает модуль замеров

`:benchmark` нужен только для замеров производительности и не влияет
на работу приложения. Если он конфликтует с версией AGP, отключите:

1. В `settings.gradle.kts` закомментировать `include(":benchmark")`
2. В `app/build.gradle.kts` закомментировать две строки:
   - `alias(libs.plugins.baselineprofile)` в блоке `plugins`
   - `baselineProfile(project(":benchmark"))` в блоке `dependencies`

## 5. Запуск на устройстве

### Подготовка телефона

1. **Настройки → О телефоне** → семь раз нажать «Номер сборки»
2. **Настройки → Для разработчиков** → включить **Отладка по USB**
3. На Xiaomi/Redmi дополнительно включить **«Установка через USB»**
   и **«Отладка по USB (настройки безопасности)»** — без них установка
   молча не проходит
4. Подключить кабелем, на телефоне подтвердить отпечаток компьютера

Проверка, что устройство видно:

```
adb devices
```

### Запуск

В Studio выбрать устройство в списке сверху и нажать **Run** (Shift+F10).

## 6. Что сделать сразу после установки

Приложение бесполезно, пока не получило роль. При первом запуске
оно само предложит пошагово:

1. **Назначить телефоном по умолчанию** — без этого не работает ничего:
   ни журнал, ни приём вызовов
2. Выдать разрешения: телефон, журнал вызовов, контакты, уведомления
3. По желанию: наложение поверх окон, исключение из оптимизации батареи

**На MIUI/HyperOS обязательно** исключить приложение из оптимизации
батареи и разрешить автозапуск в фирменной «Безопасности». Без этого
система выгружает приложение во время разговора.

Если роль не предлагается: **Настройки Android → Приложения →
Приложения по умолчанию → Телефон**.

## 7. Что проверить в первую очередь

| Проверка | Как |
|---|---|
| Журнал вызовов заполнен | Открыть приложение сразу после выдачи разрешений |
| T9-поиск | Набрать 3–4 цифры, соответствующие буквам имени |
| Исходящий вызов | Позвонить на свой второй номер |
| **Входящий со звуком** | Позвонить с другого телефона. Мелодию играет система |
| Приём с заблокированного экрана | Заблокировать телефон и позвонить на него |
| Завершение вызова | Кнопка должна быть крупной и доступной |
| Экран вызова в ландшафте | Повернуть телефон во время разговора |
| Тёмная тема на экране вызова | Включить тёмную тему, позвонить |
| Свайп по записи журнала | Свайп вправо должен звонить |
| Две SIM | Кнопка вызова делится пополам |
| Датчик приближения | Поднести к уху — экран должен погаснуть |

## 9. Сборка релиза

### Создание ключа подписи (один раз)

```
keytool -genkey -v -keystore ogneliss-release.jks ^
        -keyalg RSA -keysize 4096 -validity 10000 -alias ogneliss
```

⚠️ **Сохраните файл ключа и пароли надёжно.** Google Play привязывает
приложение к ключу навсегда: при потере выпустить обновление невозможно,
придётся публиковать новое приложение с нуля, потеряв установки и отзывы.

### Настройка

Скопировать `keystore.properties.example` в `keystore.properties`
и заполнить:

```properties
storeFile=../ogneliss-release.jks
storePassword=ваш_пароль
keyAlias=ogneliss
keyPassword=ваш_пароль
```

Файл в репозиторий не попадает — он в `.gitignore`.

### Сборка

```
gradlew.bat bundleRelease     :: App Bundle для Google Play
gradlew.bat assembleRelease   :: APK для ручной проверки
```

Без `keystore.properties` релиз соберётся с отладочной подписью:
проверить можно, опубликовать нельзя.

## 10. Если что-то не собирается

Разбор частых ошибок с причинами: **`docs/BUILD_TROUBLESHOOTING.md`**

Быстрые действия, помогающие в большинстве случаев:

```
gradlew.bat clean
gradlew.bat --stop
```

Затем **File → Invalidate Caches → Invalidate and Restart** в Studio.

Если ошибка осталась — искать в логе первую строку со словом `error`,
а не последнюю: последующие обычно следствия первой.
