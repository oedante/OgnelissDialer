# Чек-лист выпуска релиза

Проходить целиком перед каждой отправкой в Google Play.
Порядок важен: пункты сверху дешевле исправить.

## 1. Локальная проверка (минуты)

```bash
python3 scripts/prebuild_check.py    # статические ошибки сборки
python3 scripts/audit.py             # локализация, мёртвый код, комментарии
./scripts/check_no_internet.sh       # отсутствие разрешения INTERNET
./scripts/check_ringing_flag.sh      # флаг рингтона без проигрывателя
./gradlew testDebugUnitTest          # 229 юнит-тестов
./gradlew lintRelease                # статический анализ Android
```

Все пять скриптов встроены в CI и валят сборку при нарушении.

Код открыт (1.5.7): перед отправкой в GitHub — `python3 scripts/oss_audit.py`
(ключи, пароли, чужие номера и адреса). Порядок публикации — `docs/OPEN_SOURCE.md`.

## 2. Сборка

```bash
# Первый раз: создать ключ и keystore.properties по шаблону
keytool -genkey -v -keystore ogneliss-release.jks \
        -keyalg RSA -keysize 4096 -validity 10000 -alias ogneliss

./gradlew bundleRelease              # App Bundle для Play
./gradlew assembleRelease            # APK для ручной проверки
```

⚠️ **Ключ подписи сохранить в надёжном месте.** Google Play привязывает
приложение к нему навсегда: потеря означает невозможность выпустить
обновление, придётся публиковать новое приложение с нуля, потеряв
все установки и отзывы. При первой публикации включить Play App Signing —
тогда основной ключ хранит Google, а вы подписываете загрузочным.

## 2.1. Проверка release-сборки на устройстве

**Собирать и проверять нужно именно release.** Debug медленнее в два-пять
раз: в нём нет R8, нет предкомпиляции, компилятор Compose оставляет
проверки, и включён StrictMode.

Оптимизировать по ощущениям от debug — значит чинить то, чего
у пользователей не будет.

```bash
./gradlew assembleRelease
adb install -r app/build/outputs/apk/release/app-release.apk
```

Отдельно проверить после установки release:

- [ ] **Настройки не сбросились.** Если сбросились — обфускация задела
      имена enum, проверьте правило `valueOf` в `proguard-rules.pro`
- [ ] **Входящие вызовы принимаются.** Если нет — R8 вырезал сервисы
      телефонии, проверьте правило `-keep class com.ogneliss.dialer.call`
- [ ] Открытие приложения, прокрутка журнала, поиск — плавность
      должна заметно отличаться от debug

## 2.2. Baseline Profile

Даёт 20–30 % к скорости холодного старта и первой прокрутки.
Требует подключённого устройства:

```bash
./gradlew :app:generateBaselineProfile
```

**Полученный файл закоммитить** — он часть исходников, а не артефакт
сборки. Без него профиль не работает вовсе.

## 3. Проверка собранного артефакта

```bash
# Разрешения в готовом APK — глазами, а не по манифесту исходников
aapt dump permissions app/build/outputs/apk/release/app-release.apk

# INTERNET быть не должно
aapt dump permissions app/build/outputs/apk/release/app-release.apk | grep INTERNET
```

Ожидаемый список разрешений (19 штук):
`CALL_PHONE`, `READ_PHONE_STATE`, `READ_PHONE_NUMBERS`, `ANSWER_PHONE_CALLS`,
`READ_CALL_LOG`, `WRITE_CALL_LOG`, `READ_CONTACTS`, `WRITE_CONTACTS`,
`MANAGE_OWN_CALLS`, `POST_NOTIFICATIONS`, `VIBRATE`, `MODIFY_AUDIO_SETTINGS`,
`BLUETOOTH_CONNECT`, `FOREGROUND_SERVICE`, `FOREGROUND_SERVICE_PHONE_CALL`,
`SYSTEM_ALERT_WINDOW`, `SCHEDULE_EXACT_ALARM`, `RECEIVE_BOOT_COMPLETED`,
`USE_FULL_SCREEN_INTENT`.

**Ничего сверх этого списка быть не должно.** Лишнее разрешение —
повод для вопросов на ревью и падения конверсии установок.

## 4. Проверка на устройствах

Обязательный минимум — **реальные устройства**, эмулятор не подходит:
на нём нет входящих вызовов, SIM-карт и настоящей телефонии.

| Проверка | Почему именно она |
|---|---|
| Назначение диалером по умолчанию | Без роли не работает ничего |
| Входящий вызов со **звуком** | Мелодию играет система; проверить, что она звучит |
| Приём с заблокированного экрана | Самый частый сценарий |
| Завершение вызова кнопкой | Жалоба «не могу завершить» в отзывах на аналоги |
| Экран вызова в **ландшафте** | Кнопки не должны уезжать |
| Тёмная и AMOLED-темы **на экране вызова** | Здесь тема применялась не всегда |
| Две SIM: выбор карты, бейджи | Половина рынка |
| Датчик приближения у уха | Иначе щека нажимает кнопки |
| Работа после перезагрузки | Каналы уведомлений, напоминания |
| Прошивки MIUI/HyperOS, One UI, EMUI | Своя логика ролей и автозапуска |
| Android 8 / 10 / 12 / 14 / 15 | Разные ограничения телефонии |

Отдельно: **исключение из оптимизации батареи на MIUI**. Без него система
выгружает приложение во время разговора — самая частая однозвёздочная
жалоба на сторонние диалеры.

## 7. Формы в Play Console

### Declared Permissions Form ❗ самое долгое
Для `CALL_LOG` и `PHONE` подаётся отдельная декларация. Требуется:
- обоснование «приложение является диалером по умолчанию»;
- **видеодемонстрация** сценария использования разрешений;
- подтверждение, что данные не покидают устройство.

Закладывать **недели**, а не дни: ревью этой формы — самый долгий этап.
Сценарий видео: `docs/PLAY_VIDEO_SCRIPT.md`.

### Data Safety
| Поле | Ответ |
|---|---|
| Собираются ли данные | **Нет** |
| Передаются ли третьим лицам | **Нет** |
| Обоснование | Разрешение `INTERNET` отсутствует в манифесте |

⚠️ Если появится онлайн-функция, форму переписать **до** публикации сборки.

Про внешние определители: это передача данных **сторонним приложением**,
не нами. Функция выключена по умолчанию. Упомянуть в описании.
