# Ogneliss Dialer 2.9.5 (100) — сервисные коды: *#06# показывает IMEI, *#*#…#*#* передаются и на новых Android (23.11.2026)

> Автор, по «Что нового» 2.9.1: «Сервисные коды (*#06# и др.) срабатывают сразу при
> наборе — не работают».
>
> versionCode 100. Разрешения, зависимости, база, манифест — без изменений.

На телефоне не проверялось.

## Что было не так

- **\*#06#.** С 2.1.0 код уходил в `TelecomManager.handleMmi`. Но Android разбирает там
  только коды PIN/PUK (`**04*…`, `**05*…`) — IMEI системная звонилка показывает сама,
  своим окном. `handleMmi("*#06#")` отвечает «нет», и ничего не происходило: ни при
  наборе (2.9.1), ни по кнопке вызова.
- **\*#\*#код#\*#\*.** Код передаётся системе методом `TelephonyManager`, вызываемым
  через отражение: в заглушках compileSdk 37 прежнего `sendDialerSpecificSecretCode`
  нет — метод переименован в `sendDialerSpecialCode`. Искали только прежнее имя: на
  Android, где его нет, код молча не уходил.

## Что изменено

- **\*#06# — окно с IMEI**, как у системной звонилки (`ImeiDialog`): IMEI каждой SIM,
  текст выделяется, «Копировать». С Android 10 IMEI отдаётся приложению SMS
  по умолчанию (`CallActions.readImeis`, `TelephonyManager.getImei(slot)`). Не SMS по
  умолчанию — сначала пробует система (`handleMmi`), не взяла — окно «IMEI Android
  показывает только системной звонилке и приложению SMS по умолчанию» с кнопкой
  «О телефоне» (системные «Сведения о телефоне»). IMEI нигде не хранится и в журнал
  не пишется.
- **\*#\*#код#\*#\*** — оба имени метода по очереди (`SECRET_CODE_METHODS`); какое
  сработало или почему нет — строкой в журнале.

## Чего сторонняя звонилка сделать не может

- Коды производителей (Samsung `*#0*#`, `*#1234#`, меню ZTE/Nubia и т. п.) обрабатывает
  только звонилка самого производителя — внутри себя, без передачи системе. Код
  `*#*#…#*#*` срабатывает, только если на телефоне есть приложение, которое его ждёт
  (например, `*#*#4636#*#*` — «Тестирование» в настройках Android; у части прошивок его нет).
