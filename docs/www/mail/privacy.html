Политика конфиденциальности

Ogneliss Mail · Версия 1.0 · 4 октября 2026 г.

Кратко

Ogneliss Mail работает напрямую с вашими почтовыми серверами. Письма, контакты и календарь хранятся на устройстве в зашифрованном виде и передаются только этим серверам. В приложении нет рекламы, аналитики и сбора отчётов о сбоях. Разработчик не получает содержимое вашей почты.

Разработчик: Ермишин Олег Андреевич

Контакт: oedante@gmail.com

Актуальная редакция: https://ogneliss.ru/mail/privacy

3. Чего Приложение не делает

  • не показывает рекламу и не содержит рекламных SDK;
  • не собирает аналитику, отчёты о сбоях и рекламный идентификатор;
  • не продаёт и не передаёт данные третьим лицам в рекламных или иных целях;
  • не отправляет текст писем никуда, кроме ваших почтовых серверов: облачных сервисов обработки текста в Приложении нет;
  • не даёт отправителям следить за прочтением: встроенный блокировщик отключает пиксели отслеживания в письмах.

4. Вход через Google, Яндекс и Mail.ru

Для входа через аккаунт этих служб (OAuth) используется сервер разработчика по адресу ogneliss.ru/oauth. Он получает от службы одноразовый код авторизации и обменивает его на токены доступа. Токен обновления возвращается в Приложение в зашифрованном виде; сервер не ведёт базу пользователей и не хранит токены. Когда срок доступа истекает, Приложение передаёт серверу зашифрованный токен, и тот запрашивает у службы новый.

Через этот сервер не проходят письма, контакты и календарь — Приложение получает их напрямую от почтовой службы. Сервер ведёт стандартный журнал веб-сервера (IP-адрес, время и адрес запроса) для защиты от атак.

Отозвать доступ можно в настройках безопасности вашего аккаунта Google, Яндекс или Mail.ru.

5. Рабочие учётные записи

Если вы подключаете рабочую почту (например, Microsoft Exchange вашей организации), данные этой учётной записи обрабатывает и ваша организация — на своём сервере и по своим правилам. Сервер организации может потребовать блокировку экрана и выполнить удалённую очистку: по такой команде Приложение удаляет данные рабочей учётной записи с устройства. Разработчик не имеет доступа к серверам вашей организации.

  • пароли и токены — в защищённом хранилище Android;
  • резервное копирование данных Приложения в облако отключено;

  • соединения с серверами — только по TLS; доверенные центры сертификации — системные, установленные вами на устройство и, если вы их включили, сертификаты Минцифры России.

  • Удалить учётную запись в Приложении — удаляются все её данные на устройстве: письма, вложения, контакты, события, токены.
  • Удалить Приложение — удаляются все данные Приложения.
  • Вход через Google, Яндекс, Mail.ru — отзовите доступ в настройках аккаунта службы. На сервере входа данных о вас не остаётся (см. раздел 4).

3. What the App does not do

  • show ads or include advertising SDKs;
  • collect analytics, crash reports or the advertising ID;
  • sell or share data with third parties for advertising or any other purpose;
  • send message text anywhere other than your mail servers: the App uses no cloud text processing services;

4. Signing in with Google, Yandex and Mail.ru

Sign-in with these providers (OAuth) uses the developer's server at ogneliss.ru/oauth. It receives a one-time authorisation code from the provider and exchanges it for access tokens. The refresh token is returned to the App in encrypted form; the server keeps no user database and stores no tokens. When access expires, the App sends the encrypted token to the server, which requests a new one from the provider.

Messages, contacts and calendars never pass through this server — the App receives them directly from the mail provider. The server keeps a standard web server log (IP address, time and requested URL) to protect against attacks.

You can revoke access in the security settings of your Google, Yandex or Mail.ru account.

5. Work accounts

If you connect a work account (for example, your organisation's Microsoft Exchange), that account's data is also processed by your organisation, on its own server and under its own rules. The organisation's server may require a screen lock and may issue a remote wipe; on such a command the App deletes the work account's data from the device. The developer has no access to your organisation's servers.

7. Storage and security

  • passwords and tokens are kept in the Android secure storage;
  • cloud backup of App data is disabled;
  • App lock with PIN and biometrics;
  • server connections use TLS only; trusted certificate authorities are the system ones, those you installed on the device and, if you enable them, the Russian Ministry of Digital Development certificates.

  • Uninstall the App — all App data is deleted.
  • Google, Yandex, Mail.ru sign-in — revoke access in your provider account settings. No data about you remains on the sign-in server (see section 4).

The App creates no accounts with the developer, so there is nothing to delete on the developer's side. Questions: oedante@gmail.com.

Le serveur de l’organisation peut exiger un verrouillage de l’écran et ordonner un effacement à distance ; sur cette commande, l’application supprime les données du compte professionnel de l’appareil. Le développeur n’a aucun accès aux serveurs de votre organisation.
