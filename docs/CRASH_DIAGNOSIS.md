# Как достать причину падения

Написано для случая «приложение вылетает, а в logcat пусто».

## 1. Буфер падений — он отдельный

Обычный logcat очищается при перезапуске процесса, а падения хранятся
в собственном буфере и переживают его:

```
adb logcat -b crash -d > crash.txt
```

Флаг `-d` выгружает и завершает работу, не оставаясь слушать.
**Это первое, что стоит сделать** — в 90 % случаев стек находится здесь,
даже когда основной logcat пуст.

## 2. Смотреть без фильтра по приложению

Частая причина «пустого logcat»: включён фильтр по процессу приложения.
Процесс умер, фильтр перестал совпадать, и строки не показываются.

В Android Studio: **Logcat → выпадающий список процесса → No Filters**.

Из терминала — сразу целиком:

```
adb logcat -d > full.txt
```

Затем искать в файле по словам `FATAL`, `AndroidRuntime`, `OgnelissCrash`.

## 3. Собственный лог приложения

Приложение пишет стек в файл до того, как процесс умрёт, — независимо
от logcat.

**Из приложения:** Настройки → Диагностика → Отправить лог.

**Через adb**, если приложение не открывается:

```
adb shell run-as com.ogneliss.dialer.debug ls files/logs
adb shell run-as com.ogneliss.dialer.debug cat files/logs/ogneliss-log.txt > log.txt
```

Для release-сборки `run-as` не сработает — только через меню приложения.

## 4. Отметка этапа

Если стека нет нигде, остаётся понять, **что приложение делало последним**.

При падении сохраняется текущий этап, и при следующем запуске первая
строка нового лога сообщает:

```
ПРОШЛЫЙ ЗАПУСК ЗАВЕРШИЛСЯ ПАДЕНИЕМ на этапе: refresh
```

Этапы и что они означают:

| Этап | Что происходило |
|---|---|
| `startup` | Инициализация приложения |
| `permissions_changed` | Обработка только что выданных разрешений |
| `refresh` | Чтение журнала, контактов и SIM |
| `shortcuts` | Обновление ярлыков в меню значка |
| `idle` | Данные загружены, приложение ждёт действий |

## 5. Падение без исключения

Если ни стека, ни отметки нет, процесс скорее всего убила система.
Признаки в `adb logcat -d | grep -i "am_kill\|lowmemorykiller\|ANR"`.

Частые причины на конкретных прошивках:

- **MIUI / HyperOS** — приложение не добавлено в автозапуск, система
  выгружает его при первой возможности. Настройки → Приложения →
  Ogneliss → Автозапуск, и отдельно «Экономия батареи → Без ограничений».
- **Realme / Oppo / vivo** — аналогичные разделы в «Управление питанием».
- Любая прошивка — включён режим энергосбережения.

## 6. Что прислать для разбора

```
adb logcat -b crash -d > crash.txt
adb shell dumpsys package com.ogneliss.dialer.debug | grep -A 20 "runtime permissions"
```

Первое даст стек, второе — фактическое состояние разрешений на момент
падения. Вместе они обычно закрывают вопрос.
