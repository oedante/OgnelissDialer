# FlowUI — стиль интерфейса Ogneliss Dialer

Описание собрано из работающего кода, а не придумано наперёд. Правило
одно: **новый экран не вводит своих значений**. Если нужного нет —
сначала добавляем сюда и в код, потом используем.

## 2. Отступы

```
screenPadding = 12.dp    от края экрана до карточки
cardSpacing   = 4.dp     между карточками
cardPadding   = 16/8.dp  внутри карточки (горизонт./вертикаль)
```

**Почему 12, а не 16.** Карточка добавляет свои 16 по горизонтали;
вместе получается привычное расстояние от края до текста, но карточка
шире и вмещает больше.

**Крупные отступы (20–32 dp) допустимы только** в мастере разрешений,
экране согласия и подсказке о жестах: там текст читают, а не
просматривают. В списках и карточках их быть не должно.

---

## 3. Шрифты

Только стили из темы. Числами задавать размер нельзя — исключение
ниже.

| Роль | Стиль | Размер |
|---|---|---|
| Имя на экране вызова | задаётся числом | 36 sp портрет, 28 альбом |
| Заголовок экрана | `headlineSmall` | 24 sp |
| Имя в строке списка | `titleMedium` | 17 sp |
| Основной текст | `bodyLarge` | 16 sp |
| Номер, дата под именем | `bodyMedium` | 14 sp |
| Подписи, метки | `labelMedium` | 14 sp |
| Мелкие пояснения | `bodySmall` | 12 sp |

### Где числа допустимы — и почему

Семь мест на всё приложение, каждое обосновано:

| Место | Размер | Почему не стиль |
|---|---|---|
| Имя на экране вызова | 36/28 sp | Зависит от ориентации, стиля под это нет |
| Номер и статус там же | 17–18 sp | Промежуточные между `titleMedium` и `bodyLarge` |
| Подпись под значком свайпа | 10–11 sp | Мельче самого мелкого стиля: полоса узкая |
| Число в статистике карточки | 24 sp | Крупная цифра, всегда одна строка |

**Всё остальное — только стили темы.** Появилось новое число —
сначала спросите себя, почему не подходит существующий стиль.

⚠️ **Задавая `fontSize` числом от 24 sp, обязательно задайте
`lineHeight`.** Иначе интервал останется от обычного текста, и длинное
имя наложится само на себя. Множитель 1.15.

---

## 4. Цвета

Из схемы Material, чтобы тёмная тема работала сама. Три исключения —
цвета, которые должны быть одинаковыми в обеих темах:

| Цвет | Значение | Где |
|---|---|---|
| `CallGreen` | `#2E7D32` | Кнопка «Позвонить», «Ответить», свайп вызова |
| `DeclineRed` | `#C62828` | «Отклонить», «Завершить», удаление, блокировка |
| `NoteTeal` | `#4DB6AC` | Значок «i» у номеров с заметкой |

**Зелёный означает только «позвонить».** Не «успешно», не «включено» —
иначе он перестанет читаться как действие.

**Красный — только необратимое или тревожное.** Пропущенный вызов,
отклонение, удаление, блокировка.

Остальное: `primary` для акцентов и счётчиков, `onSurfaceVariant`
для второстепенного текста, `outline` для самого тихого.

## 5. Размеры элементов

```
MIN_TOUCH_TARGET   = 48.dp   минимум для любой кнопки
primaryActionHeight = 56.dp  «Позвонить» в карточке
quickActionSize    = 44.dp   ряд быстрых действий
avatarSize         = 48.dp   значок в списке (настраивается)
headerAvatarSize   = 72.dp   портрет в шапке карточки
dialKeyHeight      = 72.dp   клавиша набора (настраивается)
```

Кнопка ответа на входящем — `primaryActionHeight + 16.dp`: по ней
попадают в худших условиях, какие бывают.

## 6. Формы

| Элемент | Форма |
|---|---|
| Карточка списка, заметка, номер | `shapes.large` |
| Фишка фильтра | `shapes.small` |
| Портрет, аватар | `shapes.extraLarge` |
| Портрет на экране вызова | круг, тень 6 dp |
| Любое окно | `OgnelissDialog`, не `AlertDialog` |
| Плашка состояния вызова | круг (пилюля) |
| Панель управления вызовом | `shapes.extraLarge`, `surfaceContainer` |

**Все окна на общем контейнере.** `AlertDialog` задаёт свои 24 dp по краям,
и рядом с интерфейсом, где расстояния 4–12 dp, окно выглядит из другого
приложения. Переведены все девятнадцать. У `OgnelissDialog` заголовок —
строка, содержимое передаётся в `content`, места под значок в шапке нет:
если значок несёт смысл (предупреждение), он ставится в начало содержимого.
Высоту контейнер не ограничивает, поэтому длинному содержимому нужен
`heightIn(max = …)` вместе с прокруткой — иначе кнопки уедут за край.
Проверка 35 в `prebuild_check.py` следит, чтобы `AlertDialog` не вернулся.

**Круг только на экране вызова.** Там портрет — единственное крупное
пятно, и скруглённый квадрат спорил с круглыми кнопками управления.
В списках аватар остаётся `shapes.extraLarge`: он стоит в ряду
прямоугольных карточек, и круг выбивался бы уже он.
| Нижняя панель | `OgnelissShapeTokens.bottomPanel` (28 dp сверху) |
| Клавиша набора | `OgnelissShapeTokens.dialKey` (20 dp) |
| Главная кнопка вызова | полное скругление |

## 7. Значки

**Одно действие — один значок везде.**

| Действие | Значок |
|---|---|
| Позвонить | `Call`, зелёный |
| Написать | `AutoMirrored.Message` |
| Скопировать | `ContentCopy` |
| Поделиться | `Share` |
| Заблокировать | `Block`, красный |
| Напомнить | `Alarm` |
| Фильтры | `FilterList` |
| Меню «Ещё» | `MoreVert`, всегда последний в шапке |
| Заметка у номера без контакта | `Outlined.Info`, бирюзовый |

**Стрелки вызова, чат, «домой» — из `Icons.AutoMirrored`**: они
отражаются в арабском и иврите.

## 8. Правила компоновки

**Частое — на виду, редкое — в меню.** Граница по частоте, а не
по важности: мелодия звонка не менее важна, чем звонок, но её ставят
однажды.

**Главное действие крупнее остальных.** На карточке — «Позвонить»
во всю ширину, под ней ряд помельче. Равный вид означает равный поиск
глазами.

**Досягаемость одной рукой.** Частое внизу: панель, поиск, фильтры.
Наверху — то, к чему тянутся осознанно: назад, меню, избранное.

**Списки: перенос, а не прокрутка.** Фишки и метки переносятся
по строкам (`FlowRow`). Горизонтальная прокрутка в узкой полосе прячет
содержимое, не сообщая об этом.

**Спрятать функцию можно, её последствия — нет.** Фильтры в меню, но
значок показывает число активных: иначе пустой список выглядит как
потеря данных.

## 9. Тексты

Все строки — в ресурсах, три локали: русский, английский, немецкий.
Ни одной строки в коде.

Множественное число — через `plurals`: русскому нужны три формы.

`contentDescription` обязателен у значков без подписи. Декоративные —
`null`.

## 11. Списки и разделители

Строки внутри одной панели разделяются тонкой линией — **между
строками, не над первой и не под последней**: там уже есть край панели,
и вторая граница рядом читается как ошибка вёрстки.

```kotlin
if (index > 0) HorizontalDivider(
    color = MaterialTheme.colorScheme.outlineVariant.copy(alpha = 0.5f)
)
```

Зачем: когда у контакта три номера с одинаковыми тремя кнопками справа,
глазу не за что зацепиться — получается решётка из одинаковых
элементов, и строка теряется при взгляде вскользь.

Где применено: номера и сведения в карточке, история вызовов, правила
в списках блокировки.

Где НЕ нужно: списки, где каждая запись — отдельная карточка с фоном
и отступом (заметки, напоминания, журнал). Там разделение уже сделано
формой.

## 12. Нижние панели

Всех панелей четыре: журнал, контакты, заметки, напоминания. Они
**одинаковой высоты**, иначе нижний край прыгает при перелистывании.

| Часть | Токен | Зачем |
|---|---|---|
| Полоска сверху | `bottomPanelHandleHeight` = 20 dp | В журнале за неё тянут клавиатуру; в остальных занята пустым местом ради ровной высоты |
| Ряд содержимого | `bottomPanelRowHeight` = 68 dp | Кнопки или поле поиска |

⚠️ **Жест перелистывания живёт на полоске**, а не на всей панели.
Поле ввода перехватывает касания себе — так и должно быть, иначе в нём
нельзя было бы выделять текст, — и жест на панели с поиском
не срабатывал вовсе.

Кнопка фильтра справа от поля возвращает панели площадь, свободную
от ввода: чем больше доля поля, тем меньше остаётся жесту.

## 13. Карточка абонента

- Портрет во всю ширину, пропорция 1.9 (в ландшафте 3.2). Если
  фотографии нет — портрета нет вовсе, а не пустая панель.
- **Подпись карточки: имя → заметка → номер.** Тот же порядок,
  что в журнале: человек видит строку в списке и открывает её,
  подпись обязана совпасть.
- **Имя лежит на фотографии**, если она есть: так устроены карточки
  в почте, мессенджерах и галерее. Экономит около сорока точек
  первого экрана. Под снимком имя не повторяется.

  Затемняющий градиент снизу обязателен: белый текст на произвольной
  фотографии читается через раз. Градиент идёт до половины высоты —
  затемнить весь снимок значит превратить портрет в фон.
- **Номера под именем нет.** Если имя есть, номер в книге и перечислен
  разделом «Номера» сразу ниже, со своим типом и кнопками. Если имени
  нет, номер сам стал подписью карточки.
- **Действия — круглые кнопки, подпись под кругом.** Плитки с заливкой
  убраны: пять прямоугольников в ряд спорили за внимание между собой
  и с содержимым карточки, а подпись делила место со значком —
  из-за этого «Отправить SMS» пришлось сокращать.

  Цвет несёт смысл и только он: зелёный круг у вызова, красный значок
  у блокировки, зелёный — у снятия блокировки. Остальные круги
  нейтральные: эти действия равнозначны.

  Нажимается вся колонка, включая подпись, а не только круг.
- **Цветных подложек у разделов нет.** Заметка узнаётся по бирюзовому
  значку у заголовка — тому же, что в журнале. Правило общее: цвет
  отмечает, а не заливает.
- Разделы — `SectionPanel` с заголовком внутри панели.
- Номер под именем — только если он один: у контакта с несколькими
  там оказывался тот, по которому был последний звонок, и строка
  менялась сама собой.
- Раздел «Сведения» (почта, даты) появляется, только если есть
  что показать.

## 14. Единые компоненты

**Правило: новый экран не изобретает контейнер.** Есть два компонента,
и оба в `ui/components/OgnelissPanel.kt`.

### `OgnelissPanel`

Блок с подложкой и скруглением. Заменяет собой `Card`, одиночные
`Surface` и бывший `SectionPanel` из карточки абонента.

⚠️ `SectionPanel` был почти точной копией: та же подложка, то же
скругление, те же отступы; разница — стиль заголовка и две точки
внутреннего отступа. Копия появилась раньше общего компонента
и прожила незамеченной — ровно так и набираются «три способа сделать
контейнер».

У панели есть заголовок, значок рядом с ним и пометка `heading()`
для чтения с экрана: TalkBack умеет перескакивать по заголовкам,
и без неё человек с диктором слушает панель целиком, чтобы понять,
куда попал.

```kotlin
OgnelissPanel(title = stringResource(R.string.subscriber_numbers)) {
    // содержимое
}
```

Параметр `color` — только там, где подложка несёт смысл
(предупреждение, пояснение). В остальных случаях цвет общий.

⚠️ Тени нет намеренно. `Card` по умолчанию её рисует, и на светлой
теме получалась рамка вокруг каждого блока — экран из десятка блоков
превращался в решётку.

### `OgnelissDivider`

Линия между строками панели. Одна прозрачность на всё приложение (0.5).
До этого в дереве встречались три разные — 0.4, 0.5 и полная, — и это
было видно, когда два таких списка стояли на одном экране.

Правило: линия ставится ТОЛЬКО между строками, не над первой и не под
последней.

### Что осталось не переведённым

Разделители групп в выпадающих меню и шторках: у них другая роль —
они отделяют группы пунктов, а не строки списка, и в Material для
этого принят полный вес линии.

## 15. Меню и строки списков

**Размеры пунктов меню — общие.** `FlowUi.menuItemHeight` (56 dp)
и `FlowUi.menuItemPadding`. До этого высота задавалась приватной
константой в экране журнала, а остальные меню брали свои значения:
пункты одного вида получались разной высоты, и это видно, когда два
меню открывают подряд.

```kotlin
DropdownMenuItem(
    text = { Text(stringResource(R.string.action_call)) },
    onClick = { … },
    modifier = Modifier.heightIn(min = FlowUi.menuItemHeight),
    contentPadding = FlowUi.menuItemPadding
)
```

**Минимальная высота строки списка** — `FlowUi.rowHeight` (56 dp).
Строки ниже читаются как сплошной текст, а не как список, и промахнуться
по ним легче.

## 16. Фильтры

Вид отбора читается по устройству экрана, а не по опыту:

| Сколько условий | Чем показывается | Где |
|---|---|---|
| Несколько разом | Фишки `FilterChip` в шторке | Журнал |
| Только одно | `SingleChoiceSheet` — список с кружком | Контакты, заметки, напоминания |

Фишка намекает, что можно нажать вторую; кружок говорит, что выбор
исключительный. Путать их — значит обманывать ожидание.

⚠️ Выпадающих меню для фильтров больше нет. Меню открывалось у кнопки
и перекрывало сам список — то, по чему человек и выбирает.

Новый экран с одиночным отбором берёт `SingleChoiceSheet`, а не пишет
своё меню.

## 17. Строки списков

`OgnelissListRow` — обёртка над `ListItem`, а не свой компонент.
`ListItem` раскладывает значок, заголовок, подпись и хвост по правилам
Material, знает про TalkBack и ширину экрана; переписывать это значит
повторять чужую работу и получать свои ошибки.

Обёртка задаёт три вещи, в которых был разнобой: высоту
(`FlowUi.rowHeight`), прозрачную подложку и нажатие на всю строку.

```kotlin
OgnelissListRow(
    headline = stringResource(R.string.settings_backup_export),
    supporting = stringResource(R.string.settings_backup_export_text),
    leading = { Icon(Icons.Default.FileDownload, null) },
    onClick = { … }
)
```

⚠️ Прозрачная подложка не случайна: строки почти всегда лежат внутри
`OgnelissPanel` со своим цветом, и вторая подложка поверх первой видна
на тёмной теме.

### Где `ListItem` остался и почему

| Место | Причина |
|---|---|
| Переключатель в настройках | Заголовок не текст, а строка со значком предупреждения |
| Правило в списках блокировки | Подложка меняется при выделении |
| Шторка действий | Свой цвет пункта у блокировки и разблокировки |
| Строка разрешения | Заголовок со значком «обязательно» |
| Закреплённый контакт | Кнопки перемещения вверх-вниз в хвосте |
| История в карточке | Своя подложка под цвет раздела |

Общий признак: у них заголовок не строка текста или подложка несёт
смысл. Затащить их в общий компонент можно было бы только добавив ему
параметры «произвольный заголовок» и «свой цвет подложки» — то есть
превратив обратно в `ListItem`.

## 18. Движение

Три длительности на всё приложение, в `Motion`:

| Токен | Мс | Для чего |
|---|---|---|
| `QUICK_MS` | 200 | Появление мелочей: подсказка, пометка, пустое состояние |
| `NORMAL_MS` | 300 | Смена состояния на месте: цвет плашки вызова, раскрытие панели |
| `SLOW_MS` | 750 | Только бесконечное: мерцание заглушки списка |

Переходы между экранами заданы отдельно (`enterForward` и прочие) —
у них своя логика направления.

Раньше числа стояли по месту: 220 у пустого состояния, 300 у плашки,
750 у заглушки. Поштучно разница в 80 миллисекунд не заметна,
но приложение из-за неё ощущается несобранным.

Быстрее 150 мс глаз воспринимает как рывок, медленнее 250 — как
задержку; отсюда и выбор.

## 19. Правила проверяются машиной

Три правила единого вида проверяет `scripts/prebuild_check.py`
(проверка 37):

| Правило | Что ловит |
|---|---|
| Нет `Card` | Контейнер собран не общим компонентом |
| Нет своего `HorizontalDivider` с прозрачностью | Четвёртая по счёту прозрачность линии |
| У `DropdownMenuItem` есть `FlowUi.menuItemHeight` | Пункты меню разной высоты |

Зачем машиной: свести интерфейс — половина дела. Через месяц кто-нибудь
добавит экран со своим `Card`, потом второй, и разнобой вернётся.
Именно так он и появился: три способа сделать контейнер, каждый
«всего один раз».

Исключения перечислены в самом скрипте с причиной. Сейчас их два:
строка журнала и строка контакта — у них есть выделение
и приподнятость при выборе, чего `OgnelissPanel` не делает: панель
это блок, а не строка списка.

## 20. Каркас экрана

Экран без особой шапки берёт `ScreenScaffold`: он задаёт заголовок,
кнопку «назад», отступы под системные панели и поведение шапки
при прокрутке.

**Свой `Scaffold` допустим**, когда шапка честно другая:

| Экран | Чем отличается |
|---|---|
| Журнал, контакты | Нижние панели, режим выбора |
| Списки блокировки | Шапка переключается в режим выделения |
| Карточка | Свои действия и сворачивающийся заголовок |
| Поиск настроек | Поле ввода вместо заголовка |
| Мастер, согласие | Без кнопки «назад» |

Свести их к общему каркасу можно было бы, добавив ему параметр
«произвольная шапка» — то есть вернув обычный `Scaffold`, только
длиннее.

⚠️ **У своего `Scaffold` обязателен `contentWindowInsets =
WindowInsets.safeDrawing`.** Без него содержимое уезжает под системные
панели. Проверяется машиной (проверка 38): на этом мы спотыкались
дважды, и оба раза замечал пользователь, а не проверка.

## 21. Пустые состояния

Их три вида, и путать их не надо — разбор по тому, ЧТО пусто:

| Что пусто | Чем показывается | Пример |
|---|---|---|
| Весь экран | `EmptyState` — значок, заголовок, подсказка, иногда кнопка | Журнал, контакты, заметки, напоминания |
| Раздел внутри экрана | Короткая строка приглушённым цветом | Белый и чёрный списки на одном экране |
| Пусто по существу дела | Объяснение в несколько строк с кнопкой | Внешние определители: их нет у большинства |

Полный `EmptyState` со значком в разделе, где рядом есть другой список,
выглядит как поломка страницы: два значка на одном экране спорят
за внимание и делают пустоту главным содержимым.

А объяснение на три строки нужно там, где пустота — это норма, которую
человек принимает за поломку. Экран сторонних справочников именно
такой: их нет на большинстве телефонов.

⚠️ Экраны, где пусто не бывает (быстрый набор — всегда девять клавиш,
закреплённые — всегда строка «Закрепить»), пустого состояния
не получают. Пустое состояние для невозможного случая — это код,
который никто никогда не увидит и некому будет поправить, когда
он сломается.

## 22. Как проверять

```
python3 scripts/prebuild_check.py   # структура, импорты, ресурсы
python3 scripts/audit.py            # неиспользуемое, переводы
```

Проверки не ловят стиль целиком — часть правил соблюдается
при чтении кода. Две проверки на это были написаны и удалены:
они не срабатывали на подставленных ошибках, а неработающая проверка
хуже отсутствующей.
