# Ogneliss Dialer 2.3.0 (65) — второй вызов, удержание, конференция (12.11.2026)

> Автор, 12.11.2026: «Логика работы со вторым вызовом во время разговора, удержанием
> вызова, конференцией исправна?» и «давай поднимем версию до 2.3.0».
>
> versionCode 65. Входит всё из 2.2.x (2.2.0 — SMS как в мессенджерах, 2.2.1–2.2.2 —
> интерфейс по образцу Ogneliss Mail, 2.2.3 — по журналу с realme).
> «Что нового» — `store/whats_new_2.3.0.txt`. Разрешения, зависимости и база не менялись.

Проверено по коду и сверено с системным диалером Android (InCallUI, Telecom
CallsManager); на телефоне с двумя линиями не проверялось — это нужно сделать
обязательно (сценарии внизу).

## Что было неверно и что исправлено

| Сценарий | Было | Стало |
|---|---|---|
| «Переключить» линии | `hold()` текущего и сразу `unhold()` удержанного. Telecom при `unhold()` сам ставит активный на удержание — выходило два запроса удержания; на VoLTE второй отклоняется, и обе линии могли остаться на удержании | Только `unhold()` удержанного; удержание текущего и «обмен» для сети делает Telecom |
| «Завершить и ответить» (второй входящий) | `disconnect()` текущего и сразу `answer()` второго — Telecom видел текущий ещё живым и пытался его удержать; на части сетей второй не принимался | Ответ — когда текущий перешёл в «завершён»; не дождались за 2 с — отвечаем всё равно (так же системный диалер) |
| Плитка «Удержать» | Горела и при `CAPABILITY_SUPPORT_HOLD` («сеть умеет, но сейчас нельзя») — нажатие ничего не делало | Только при `CAPABILITY_HOLD` |
| «Удержать» при второй линии на удержании | Были и «Удержать», и «Переключить»; «Удержать» ставило на удержание обе линии | При второй линии — только «Переключить» |
| «Добавить вызов» | По своим условиям; Telecom мог отклонить набранный номер (экстренный вызов, предел вызовов) | Ещё и по ответу Telecom (`canAddCall`), обновляется по `onCanAddCallChanged` |
| Удержанная линия на экране | Мелкая серая строка «На удержании: …» | Плашка с значком паузы; касание переключает на неё |
| Второй входящий, когда первый на удержании и экран погас | В 2.2.3 экран не будился (считалось «у уха») | Будится; не будится только во время разговора или набора |

## Что проверено и верно

- Ответ на второй входящий с удержанием текущего — `answer()` второго; Telecom сам
  ставит текущий на удержание (кнопка в плашке второго вызова и в уведомлении).
- Отклонить второй — `reject()` именно второго (плашка, уведомление, «Отклонить
  с сообщением» отвечает второму).
- Завершить при двух линиях — завершается активная, удержанная остаётся на удержании
  с плиткой «Продолжить» (как в системном диалере: сама не возобновляется).
- Объединить — по `conferenceableCalls`, иначе `mergeConference()`; участники
  конференции списком, «отключить» и «отдельно» — только где сеть разрешает.
- Экран вызова не закрывается, пока есть хоть один вызов.

## Проверить на телефоне (две SIM или вторая линия)

1. Разговор → второй входящий → «Удержать и ответить» → «Переключить» несколько раз.
2. Разговор → второй входящий → «Завершить и ответить».
3. Разговор → «Добавить вызов» → набор → «Объединить» → отключить одного участника.
4. Первый на удержании, экран погас → второй входящий: экран должен включиться.
5. На VoLTE и без него (часть сетей ведёт удержание по-разному).
